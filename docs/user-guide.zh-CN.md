# xreal-ppt-skill 用户教程

本教程面向第一次使用 Agent 或 Skill 的用户，帮助你准备素材、安装并正确调用 `xreal-ppt-skill`，最终得到一套可以离线打开、横向翻页的 XREAL Style 网页演示文稿。

## 1. 先确认你会得到什么

本 Skill 的标准交付物是：

- `index.html`：浏览器直接打开的网页演示文稿
- `assets/`：字体、Logo 和必要的本地运行资源
- `images/`：实际使用的图片或截图
- 来源材料较完整时，还会有 `content-coverage.json`，用于检查原始内容是否被遗漏

它默认不会生成：

- PowerPoint `.pptx` 文件
- 把每页 PDF 截图后塞进 PPTX 的文件
- 需要联网才能正常演示的网页
- 可以在 PowerPoint 中逐元素编辑的源文件

如果你必须交付 `.pptx`，这个 Skill 不是合适工具。它适合需要 XREAL 品牌视觉、浏览器演示、离线评审和网页动效的场景。

## 2. 最稳妥的使用方式

对于没有经验的用户，建议把“安装”和“制作演示文稿”分成两个任务。这样可以避免 Agent 安装完成后仍然沿用通用 PPTX 工作流。

### 第一步：安装 Skill

在 Codex 中可以直接输入：

```text
请使用 $skill-installer 安装这个 Skill：
https://github.com/IF-Lawrence/xreal-ppt-skill

安装完成后确认可以通过 $xreal-ppt-skill 调用。本次先不要制作演示文稿。
```

也可以在终端运行：

```bash
npx skills add https://github.com/IF-Lawrence/xreal-ppt-skill --skill xreal-ppt-skill
```

安装后，在 Agent 的 Skill 列表中确认能看到 `xreal-ppt-skill`。Codex 中可以输入 `$` 或打开 `/skills` 查找。如果刚安装后没有出现，重新启动 Codex，再开始制作任务。

### Skill 文件夹在哪里

在 macOS 上，Codex 默认把这个 Skill 安装到：

```text
/Users/你的用户名/.codex/skills/xreal-ppt-skill/
```

也可以把它理解为：

```text
~/.codex/skills/xreal-ppt-skill/
```

在 Finder 中按 `Command + Shift + G`，输入上面的路径即可打开。当前电脑若自定义了 `CODEX_HOME`，实际位置则是 `$CODEX_HOME/skills/xreal-ppt-skill/`。如果不确定，可以让 Agent 查找：

```text
请告诉我当前安装的 $xreal-ppt-skill 绝对路径，并确认其中存在 SKILL.md、assets、references 和 scripts。
```

安装目录中的主要内容是：

```text
xreal-ppt-skill/
├── SKILL.md       # Agent 使用本 Skill 时首先读取的规则和工作流
├── assets/        # HTML 模板、品牌 Logo、字体和官方产品图片
├── references/    # 版式、品牌、内容保真和校验规范
├── scripts/       # 校验以及复杂图表离线化工具
└── docs/          # 用户教程等说明文档
```

一般用户不需要手动修改这些文件。直接修改安装目录可能导致更新失败，或在后续更新时被覆盖。

Skill 安装目录不是演示文稿的输出目录。每次任务生成的 `index.html`、`images/` 和其他交付文件，应放在你指定的独立项目文件夹中，例如：

```text
/Users/你的用户名/Documents/XREAL-Projects/AURA-Channel-Deck/
```

不要要求 Agent 把成稿写进 `~/.codex/skills/xreal-ppt-skill/`。

### 第二步：新建任务并显式调用

新任务的第一行写：

```text
使用 $xreal-ppt-skill 完成下面的任务。
```

不要只写“制作 PPT”。“PPT”容易被通用演示文稿工具理解为 `.pptx`；应明确写“XREAL Style 网页演示文稿”以及“最终交付 `index.html`”。

## 3. 开始前需要准备什么

### 3.1 最少需要提供的信息

即使素材很完整，也建议告诉 Agent：

- 面向谁：管理层、渠道、客户、合作伙伴、销售团队或内部研发
- 使用场景：发布会、渠道培训、销售提案、业务复盘或项目评审
- 演示时长：例如 10、20 或 30 分钟
- 演示语言：中文、英文、日语或混排
- 必须保留的内容：数字、结论、案例、法务措辞、行动项等
- 可以调整的内容：顺序、分页、标题措辞、图片裁切等
- 希望交付到哪个文件夹

页数不是必填项。没有经验时，可以让 Agent 根据内容量建议页数。若你指定固定页数，同时又要求完整保留大量原文，应明确“内容放不下时先告诉我，不要自行摘要”。

### 3.2 优先提供结构清晰的 Markdown

如果条件允许，最推荐的内容输入是结构清晰的 Markdown（`.md`）。Markdown 的标题层级、段落、列表、表格和图片引用都能被 Agent 直接识别，比零散聊天记录、截图或没有层级的长文本更不容易产生误解。

这不代表所有材料都必须转换成 Markdown：已有 PDF、PPTX、DOCX 和表格仍可直接提供。但如果材料来自多个文件、结构混乱，或你对内容保留要求很高，建议额外整理一份 Markdown 作为主内容稿，原文件作为核对和视觉参考。

一份容易使用的 Markdown 应做到：

- 使用 `#`、`##`、`###` 表达章节层级，不用字体大小或空行模拟标题
- 一个章节尽量只表达一个主题，并明确希望用户理解的结论
- 数据写清单位、时间范围、统计口径和来源
- 图片使用文件路径或清晰的占位说明，注明图片意图，而不只是写“放张图”
- 明确标注“必须保留”“可以改写”“可以省略”和“待确认”内容
- 不要提前把完整原文压缩成只有几个关键词；让 Agent 在保留信息的前提下规划页面

可以直接使用下面的模板：

```markdown
# 演示文稿标题

## 基本信息

- 受众：渠道销售团队
- 场景：季度培训
- 演示时长：25 分钟
- 语言：中文
- 目标：让渠道理解产品定位、核心卖点和标准 Demo 流程

## 内容处理要求

- 必须保留：产品参数、价格、适用范围、风险说明、行动项
- 可以调整：章节顺序、分页、标题措辞
- 禁止省略：所有带数字的结论和法务限定语
- 页数：由内容决定；需要摘要时先征求确认

## 1. 市场背景

### 本节结论

线下体验是高意向客户完成决策的关键环节。

### 原始内容

[在这里写完整内容，不要只写关键词]

### 数据

- 指标：Demo 后进入报价阶段的客户比例
- 数值：42%
- 时间范围：2026 Q1–Q2
- 统计口径：完成线下 Demo 的有效商机
- 来源：Channel CRM，2026-07-31 导出

### 图片

- 文件：images/store-demo.jpg
- 用途：展示渠道门店中的实际体验场景
- 注意：保留人物和眼镜主体，不要裁掉右侧操作台

## 2. 产品定位

### 本节结论

[一句明确结论]

### 原始内容

[完整段落、列表、案例和限制条件]

## 待确认事项

- [ ] 价格是否使用建议零售价
- [ ] 客户案例是否允许公开名称
```

如果你不想自己整理，可以把原始文件交给 Agent，并先要求：

```text
请先读取这些材料并整理成一份结构清晰的 Markdown 内容稿，保留所有事实、数据、限定条件、案例和行动项。先把 Markdown 给我确认，不要立即制作演示文稿。
```

确认内容稿后，再新建任务或继续明确调用 `$xreal-ppt-skill` 制作网页演示文稿。

### 3.3 推荐的素材目录

不强制整理，但下面的结构最容易让 Agent 理解：

```text
项目资料/
├── source/          # PDF、PPTX、DOCX、Markdown、表格
├── images/          # 产品图、截图、照片、Logo
├── data/            # CSV、XLSX、数据说明
└── notes.md         # 受众、目标、必须保留内容、特别说明
```

文件名尽量表达内容，例如：

```text
AURA-渠道销售策略.pdf
竞品价格对比.xlsx
产品佩戴场景-横版.jpg
必须保留内容.md
```

不需要为了使用 Skill 大规模重命名已有文件；只要在指令里写清每个文件的作用即可。

## 4. 不同文档类型是否需要预处理

| 素材类型 | 是否建议预处理 | 准备建议 |
|---|---|---|
| 结构清晰的 Markdown | 最推荐，通常无需预处理 | 保留标题层级、完整正文、数据口径、图片路径和内容处理要求，可直接作为主内容稿 |
| 可搜索文字的 PDF | 通常不需要 | 直接提供文件路径；说明是否要逐页重建、保留原结构或重新组织叙事 |
| 扫描版 PDF | 建议 OCR | 先生成可搜索文字；同时保留原 PDF，便于核对版面、图片和文字位置 |
| 加密 PDF | 需要 | 提供可正常打开的副本，或先解除访问限制 |
| PPTX | 建议先清理隐藏页 | 提交前删除所有不应参与制作的隐藏页；需要使用的隐藏页应先取消隐藏。若视觉保真很重要，可同时提供导出的 PDF 作为参考 |
| DOCX / TXT | 通常不需要 | 保留标题层级；结构混乱或来自多个文件时，建议整理成 Markdown 主内容稿 |
| XLSX / CSV | 建议补充口径 | 说明字段含义、单位、时间范围、样本量、数据来源和希望表达的结论 |
| PNG / JPG / WebP | 通常不需要 | 尽量使用清晰原图；截图不要裁掉标题栏、坐标、图例或来源 |
| 网页链接 | 视访问情况 | 登录后才能访问的内容最好导出成 PDF 或保存到本地；告诉 Agent 哪些页面最重要 |
| 多个零散文件 | 建议增加说明 | 写一个 `notes.md`，列出优先级、文件关系和哪些内容必须使用 |
| 只有主题或一句 brief | 不需要 | 提供受众、目标和演示时长；Agent 会使用 `brief-generated` 模式规划内容 |

### 扫描版 PDF 怎么判断

尝试在 PDF 阅读器中选中一段文字：

- 可以选择并复制：通常不需要 OCR
- 只能选中整块图片：建议先 OCR
- 复制出来乱码：建议 OCR，并保留原文件供视觉核对

### PPTX 隐藏页怎么处理

提交 PPTX 前，请先删除所有不应参与新演示文稿制作的隐藏页。隐藏页常包含过期版本、内部备注、未发布内容或废弃方案；不要依赖“隐藏”状态来阻止 Agent 读取和使用这些内容。

如果某张隐藏页仍需要作为内容或设计参考，请先取消隐藏，或在任务指令中明确写出页码和用途。删除前如需保留历史版本，请先另存一份原始备份。

### 数据材料需要补充什么

不要只给一张没有说明的表。至少补充：

```text
指标：渠道转化率
单位：%
时间范围：2025 Q1–2026 Q2
统计口径：完成演示且进入报价阶段的客户
数据来源：Channel CRM，2026-07-31 导出
希望表达：线下 Demo 对高意向客户的转化贡献明显
```

这能避免 Agent 误读分母、混合不同时间范围，或者为了画图自行猜测结论。

## 5. 一条好指令应该包含什么

推荐按以下顺序写：

1. 显式调用 `$xreal-ppt-skill`
2. 明确交付物是网页 `index.html`
3. 提供素材的绝对路径或上传文件，并说明哪个文件是主内容稿；条件允许时优先使用结构清晰的 Markdown
4. 说明受众、场景、时长和语言
5. 说明内容保留要求
6. 说明图片、截图和数据如何处理
7. 说明页数是固定、建议值还是可调整
8. 写明禁止事项，例如禁止 PPTX、禁止整页嵌入 PDF
9. 指定输出目录

### 最短可用指令

```text
使用 $xreal-ppt-skill，将这份材料制作成 XREAL Style 网页演示文稿：
[文件路径]

最终交付 index.html 及必要本地资产，不要生成 PPTX。请根据内容建议页数，并保留所有关键数据、结论和限定条件。
```

### 推荐的完整指令骨架

```text
使用 $xreal-ppt-skill 完成下面的任务。

目标：将 [素材名称] 重建为 XREAL Style 网页演示文稿。
素材：[绝对路径或上传文件]
主内容稿：[结构清晰的 Markdown 文件路径；如没有，请注明主要依据哪个文件]
受众：[受众]
场景：[演示场景]
时长：[预计时长]
语言：[中文 / 英文 / 日语 / 混排]

内容要求：
- 使用 source-faithful 内容保真模式。
- 理解各章节或各页的意图后重新编排，但不要随意删除、概括或弱化原始文本。
- 必须保留所有数字、统计口径、限定条件、风险、案例、引用和行动项。
- 可以调整分页、顺序和视觉表达，但不能改变原意；`source-faithful` 不等于视觉保真，默认不要继承原材料的配色、背景、字体、装饰或旧版式，成稿仍须遵循 XREAL Style。
- 内容无法容纳时优先增加页面；如果必须压缩，先列出拟删减内容并等待确认。

媒体要求：
- 优先使用用户提供的图片和 Skill 内官方资产。
- 截图、UI、代码和数据图需要保真展示。
- 禁止把原始 PDF 页面整页渲染成图片后嵌入。

交付要求：
- 最终交付物必须是可离线打开的 index.html 及必要本地资产。
- 禁止生成 PPTX。
- 输出到：[目标文件夹]
- 完成后运行 Skill validator，并逐页检查溢出、字体、图片和内容覆盖。
```

## 6. 常用场景的可复制指令

### 6.1 将 PDF 重建为网页演示文稿

```text
使用 $xreal-ppt-skill，将以下 PDF 重建为 XREAL Style 网页演示文稿：
'/Users/你的名字/Downloads/AURA Channel Sales Deck/AURA Channel Sales Deck.pdf'

受众是渠道销售团队，演示时间约 25 分钟，使用英文。

要求：
- 最终交付 index.html，不要生成 PPTX。
- 禁止把 PDF 页面作为整页图片嵌入。
- 理解每页的销售意图、信息结构和前后关系，再映射到 XREAL 锁定版式。
- 使用 source-faithful 模式，不要随意修改或简化文本、数字、限定条件和行动项。
- 可以调整分页和视觉结构；如果完整保留需要更多页面，请增加页面，不要静默摘要。
- 输出到 '/Users/你的名字/Documents/AURA-web-deck/'。
```

### 6.2 将 Markdown 或 Word 文档制作成演示文稿

```text
使用 $xreal-ppt-skill，将以下文档制作成 XREAL Style 网页演示文稿：
'/path/to/product-strategy.md'

面向管理层，演示 15 分钟，中文。
请保留文档中的决策、依据、风险和下一步行动，允许重组章节顺序，但不要把论证过程只压缩成结论。
页数由内容决定，建议控制在 10–14 页；若超出请说明原因。
最终交付 index.html，不要生成 PPTX。
```

### 6.3 重构旧 PPTX

```text
使用 $xreal-ppt-skill，将以下旧 PPTX 重构成 XREAL Style 网页演示文稿：
'/path/to/old-deck.pptx'

我已删除所有不应参与制作的隐藏页；当前文件中的全部页面都可以作为输入材料。
这不是简单换皮：请理解每页目的、识别重复内容并重新规划节奏。
但未经确认不得删除数据、客户案例、产品限制和承诺事项。
原 PPT 中的截图和图表优先保真使用，不要整页截图旧 PPT。
最终交付 index.html 及本地资产，不要输出新的 PPTX。
```

### 6.4 使用表格制作数据汇报

```text
使用 $xreal-ppt-skill，基于以下数据制作 XREAL Style 网页汇报：
'/path/to/channel-performance.xlsx'
'/path/to/metrics-notes.md'

受众是区域销售负责人，演示 20 分钟。
先核对字段、单位、时间范围和统计口径，再选择图表。
每张图必须有明确结论、单位、图例和来源；不同量纲不要强行放在同一坐标轴。
不要自行补造数据。最终交付 index.html，不要生成 PPTX。
```

### 6.5 只有想法，没有现成文档

```text
使用 $xreal-ppt-skill，为“AURA 渠道伙伴入门”制作一套 XREAL Style 网页演示文稿。

受众：第一次销售 AURA 的渠道伙伴
场景：30 分钟线上培训
语言：中文
目标：让伙伴理解产品定位、目标客户、核心卖点、Demo 流程和常见异议

目前没有完整原稿，请先给出页序和仍需我补充的事实清单。没有依据的产品参数、市场数据和客户案例不要自行编造。
最终交付 index.html，不要生成 PPTX。
```

### 6.6 修改已经生成的网页演示文稿

```text
使用 $xreal-ppt-skill 修改以下现有网页演示文稿：
'/path/to/deck/index.html'

修改要求：
- 第 3 页保留原文，只调整信息层级和间距。
- 第 6 页把表格改为适合该数据形状的图表。
- 封底保持大号 Thanks 居中，小号 XREAL Logo 位于底部中央。
- 不要改变其他页面内容。

修改后重新运行 validator，并保留可编辑源文件。
```

## 7. 三种内容模式怎么选择

### `source-faithful`：有完整原始材料时的默认模式

适合 PDF、PPTX、DOCX、Markdown、会议纪要和成体系资料。Agent 会建立内容覆盖清单，避免遗漏原始事实；它只保证内容语义，不会默认复制原材料的视觉主题，成稿仍按 XREAL Style 重建。

你通常不需要自己制作 `content-coverage.json`；这是 Agent 的工作。你只需要说明哪些内容绝对不能删除。

### `editorial-summary`：明确需要摘要时

适合管理层摘要、5 分钟速览或明确要求“只保留核心结论”的任务。建议同时说明允许省略什么，例如：

```text
使用 editorial-summary 模式。可以省略实施细节和重复案例，但必须保留结论依据、全部风险和最终行动项。
```

### `brief-generated`：只有主题或短需求时

适合从零策划。Agent 可以设计叙事，但不能把推测内容伪装成已确认事实。产品参数、客户案例和市场数据仍应由你提供或确认。

## 8. Skill 本身如何工作

下面是 `SKILL.md` 规定的内部流程。这些步骤由 Agent 执行，用户通常不需要自己运行命令。你可以展开各阶段了解 Agent 此时在做什么。

<details>
<summary>Step 0：检查 Skill 是否有更新</summary>

Agent 首先检查安装目录所在的 Git 仓库是否落后于远端版本。同一个任务只检查一次。

- 没有更新：直接继续，不打断用户
- 有更新：说明更新数量和摘要，询问是否先更新
- 本地有未提交修改或版本发生分叉：不会自动覆盖、合并或重置
- 无法联网或安装目录不是 Git 仓库：说明情况后继续使用当前版本

</details>

<details>
<summary>Step 1：理解需求并建立内容覆盖清单</summary>

Agent 读取受众、场景、时长、语言、原始文件和内容保留要求。用户提供 Markdown、PDF、PPTX、DOCX 或其他成体系材料时，默认进入 `source-faithful` 内容保真模式。

Agent 会把原始材料拆成可追踪的来源项，并在项目输出目录建立 `content-coverage.json`。如果内容放不下，应优先调整版式或增加页面，而不是自行摘要。

</details>

<details>
<summary>Step 2：把模板和必要资产复制到项目输出目录</summary>

Agent 从 Skill 安装目录的 `assets/` 读取 HTML 模板、字体、Logo 和官方媒体，但不会直接在安装目录中制作成稿。它会在用户指定的独立项目文件夹中建立 `index.html`、`assets/` 和 `images/`。

这个复制过程能让最终演示文稿使用相对路径并支持离线打开，也能避免修改 Skill 自身的模板和资产。

</details>

<details>
<summary>Step 3：规划页面并生成网页演示文稿</summary>

Agent 先规划内部页序、内容对应关系、锁定版式和图片槽位，再填充 HTML。它会根据整套内容选择英文、中文或日语字体体系，并从 XREAL 官方资产中选择与产品和语义匹配的图片。

正文只能使用登记过的 XREAL 版式；封面和封底使用专用结构。封底固定突出大号 `Thanks`，小号 XREAL Logo 位于底部中央。

</details>

<details>
<summary>Step 4：运行校验和逐页视觉检查</summary>

Agent 先运行 Skill 安装目录 `scripts/` 中的校验器，检查版式登记、内容覆盖、图片槽位、溢出和底部安全区。随后在真实浏览器中渲染全部页面，并检查文字、图片、图表、Logo、裁切、对比度和页面层级。

发现问题后需要修复、重新校验并复审。校验器通过不等于视觉检查完成。

</details>

<details>
<summary>Step 5：本地预览、整理交付并说明结果</summary>

全部页面通过后，Agent 在项目输出目录中交付 `index.html` 及必要资产，并说明内容覆盖和视觉 QA 结果。用户要求分享时，还应确认全部资源均为目录内相对路径，并将整个交付目录打包为 ZIP。

</details>

完整流程可以概括为：

```text
检查更新
  → 理解需求与清理输入
  → 建立内容覆盖清单
  → 复制模板到项目输出目录
  → 规划页序、版式和媒体
  → 生成 index.html
  → 自动校验
  → 全页渲染与视觉复审
  → 修复并复验
  → 整理交付与分享包
```

## 9. 如何验收结果

至少检查以下内容：

- 双击 `index.html` 能否离线打开
- 左右方向键、滚轮或触控能否翻页
- `ESC` 能否打开索引视图
- 所有文字、图片和图表是否完整显示，没有被裁掉或进入底部导航区
- Agent 支持图像输入时，是否实际检查了全部最终页面截图，而不是只检查 HTML、代码或抽样页面
- 字体是否正确：英文、中文、日文是否与整套语言语境一致
- PDF、PPTX 或文档中的关键内容是否都出现
- 数字、单位、时间范围、来源和限定条件是否准确
- 是否出现整页 PDF 截图、整页旧 PPT 截图或不可编辑的大图替代内容
- 最终文件是否为 `index.html`，而不是 `.pptx`
- 封底是否为大号 `Thanks` 居中、小号 XREAL Logo 底部中央

来源材料较完整时，可以要求 Agent 报告：

```text
请汇报内容覆盖项总数、已包含项、经我批准的遗漏项，并列出每个遗漏项的原因。
```

## 10. 最终文件怎么使用和分享

### 10.1 在自己的电脑上演示

1. 如果收到的是 ZIP 压缩包，先完整解压，不要直接在压缩包预览窗口中打开。
2. 保持 `index.html`、`assets/`、`images/` 和其他交付文件的相对位置不变。
3. 使用最新版 Chrome、Edge 或 Safari 打开 `index.html`。演示前将浏览器缩放设为 100%，再进入全屏。
4. 断开网络测试一次，确认字体、图片、视频和图表仍能正常显示。

演示时不要只复制 `index.html` 到桌面。即使首页能打开，引用的图片、字体或脚本也可能因为配套目录缺失而无法加载。

### 10.2 发给同事或客户

最稳妥的方式是分享整个交付目录的 ZIP 压缩包：

```text
xreal-deck/
├── index.html
├── assets/
├── images/
└── content-coverage.json  # 如果有
```

接收方下载后应先完整解压，再打开 `index.html`。通过邮件、企业网盘或即时通讯工具分享时，不要只发送 HTML 文件，也不要改变目录中的文件名和层级。

可以在任务中直接要求 Agent：

```text
请把最终交付文件整理到一个独立目录中，确保所有资源都使用目录内的相对路径，不引用我电脑上的绝对路径或目录外文件。完成离线测试后，再生成一个可直接分享的 ZIP 压缩包，并附上简短的打开说明。
```

除非 Agent 已明确确认交付物是完全自包含的单文件 HTML，否则不要假设只分享 `index.html` 就能正常运行。

### 10.3 发布成可以点击的网页链接

`file:///Users/.../index.html` 只是你本机的文件地址，其他人无法访问。若希望接收方点击链接直接观看，需要把整个交付目录上传到支持静态网页的网站、公司内部静态服务器或对象存储，并让服务器以 `index.html` 作为入口页。

上传时必须保持文件结构不变。发布后至少检查首页、末页、图片、字体、图表、翻页和全屏效果。演示文稿包含内部数据、客户信息或未发布产品时，应使用公司批准的受控环境，不要上传到公开网站。

如果你不熟悉网页发布，可以把下面的要求交给具备部署权限的同事或 Agent：

```text
请将这个网页演示文稿部署为静态网站，保持现有目录结构和相对路径，并提供可访问链接。发布前先确认内容不包含禁止公开的信息；未经我确认，不要发布到公开互联网。
```

## 11. 常见问题与纠正指令

### Agent 生成了 PPTX

原因通常是没有显式调用 Skill，或者指令只写了“制作 PPT”。纠正方式：

```text
停止当前 PPTX 流程。请显式加载并完整读取 $xreal-ppt-skill。
最终交付物必须是 XREAL Style 网页演示文稿 index.html，禁止生成 PPTX。
```

### Agent 把 PDF 每页作为图片嵌入

```text
不要把 PDF 页面整页渲染成图片。PDF 是内容来源，不是最终页面素材。
请提取并理解每页的文字、数据、结构和叙事目的，再使用 XREAL HTML 锁定版式重建。
只有原始截图、产品图或必须保真的视觉证据可以作为图片使用。
```

### 原文被大量摘要

```text
切换为 source-faithful 模式。请先建立 content-coverage.json，并将原始材料拆成 SRC-xxx 来源项。
未经我确认不得省略任何事实、数据、限定条件、案例、风险、引用和行动项。
内容放不下时增加页面，不要自行摘要。
```

### 页面文字太小或内容拥挤

```text
不要继续缩小字号。请删除无信息价值的视觉填充、调整版式或增加页面。
如果固定页数与完整保留冲突，请先告诉我需要增加多少页。
```

### Agent 找不到本地文件

本地路径只对运行在同一台电脑上的 Agent 有效。如果任务运行在云端或另一台电脑上，需要上传文件，或将任务切换到能访问该路径的本地环境。

包含空格的路径建议使用单引号包起来：

```text
'/Users/你的名字/Downloads/AURA Channel Sales Deck/AURA Channel Sales Deck.pdf'
```

### 安装后仍然没有使用 Skill

结束安装任务，新建一个任务，并在第一行显式写：

```text
使用 $xreal-ppt-skill。
```

如果 Skill 列表中仍然没有出现，重新启动 Codex，并确认安装目录中存在 `xreal-ppt-skill/SKILL.md`。

## 12. 提交任务前的快速检查

复制下面的清单，确认后再发送任务：

```text
□ 已安装并能看到 $xreal-ppt-skill
□ 安装和制作最好分成两个任务
□ 已明确最终交付 index.html，禁止 PPTX
□ 已提供素材路径或上传文件
□ 优先提供了结构清晰的 Markdown 主内容稿，或说明了哪个文件是主来源
□ 已说明受众、场景、时长和语言
□ 已说明必须保留的内容
□ 已选择 source-faithful / editorial-summary / brief-generated
□ PDF 不是整页图片嵌入用途
□ 扫描 PDF 已做 OCR，或已提醒 Agent 需要 OCR
□ PPTX 已删除所有不应参与制作的隐藏页；需要使用的隐藏页已取消隐藏或明确说明
□ 数据材料包含单位、时间范围、口径和来源
□ 已说明页数能否调整
□ 已指定输出目录
□ 已要求完成后运行 validator 和内容覆盖检查
□ 如需分享，已要求交付目录使用相对路径并生成完整 ZIP 压缩包
```

如果不确定怎么写，优先使用本教程第 5 节的“推荐完整指令骨架”，替换方括号中的内容即可。
