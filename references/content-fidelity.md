# 内容保真协议

当用户提供文章、Markdown、会议纪要、旧 PPT、文档、表格说明或其他成体系原始材料时，先执行本协议，再规划叙事和版式。目标是把材料改编成演示文稿，而不是在用户未授权时把它替换成摘要。

## 1. 选择内容模式

在 `<body>` 上声明且只声明一种模式：

| `data-content-mode` | 使用条件 | 内容处理权限 |
|---|---|---|
| `source-faithful` | 用户提供了成体系原始材料；默认模式 | 可调整顺序、拆页、合并真正重复的表述和忠实转述；不得自行省略事实、数据、限定条件、案例、引用、决策或行动项 |
| `editorial-summary` | 用户明确要求摘要、精简、提炼，或明确批准删减方案 | 可按批准范围压缩，但仍需记录未采用内容及原因 |
| `brief-generated` | 用户只给出主题、短 brief 或零散要求，没有可逐项覆盖的原始材料 | 可按叙事需要生成；不得把模型补写内容伪装成用户原文或已确认事实 |

“做成 PPT”“控制在 N 页”“更简洁”“更有冲击力”本身不等于授权删除大量原文。若固定页数与完整保留冲突，先增加信息承载页或向用户说明冲突；不要静默切换到摘要模式。

## 2. 建立覆盖清单

`source-faithful` 与 `editorial-summary` 模式必须在写 slide 前，将原始材料拆成可核对的语义单元并写入项目根目录的 `content-coverage.json`。语义单元以一项独立事实、数据、论点、限定条件、案例、引用、决策或行动项为边界，不按句号机械切分。

为每项分配稳定 ID：`SRC-001`、`SRC-002`……。不要因为多个来源项会落在同一页就合并 ID。清单不得包含不必要的敏感原文全文；`label` 使用足以核对的短标签，必要时记录来源章节或页码。

```json
{
  "version": 1,
  "mode": "source-faithful",
  "sourceLabel": "用户提供的产品策略文档",
  "items": [
    {
      "id": "SRC-001",
      "label": "目标用户与使用场景",
      "kind": "claim",
      "disposition": "included",
      "slideIds": ["slide-02"]
    },
    {
      "id": "SRC-002",
      "label": "成本数据及统计口径",
      "kind": "data",
      "disposition": "included",
      "slideIds": ["slide-04"]
    }
  ]
}
```

字段规则：

- `version` 固定为 `1`。
- `mode` 必须与 `<body data-content-mode>` 一致。
- `kind` 使用 `claim`、`data`、`constraint`、`example`、`quote`、`decision`、`action` 或 `context`。
- `disposition` 只能是 `included` 或 `omitted`。
- `included` 必须提供至少一个真实存在的 `slideIds`。
- `omitted` 必须提供具体 `reason`。在 `source-faithful` 模式中还必须写 `userApproved: true`；未获用户明确同意不得遗漏。

每个承载原始内容的正文 section 必须有稳定 `id`，并用 `data-source-refs` 回指来源项：

```html
<section id="slide-04" class="slide light" data-layout="S23"
  data-source-refs="SRC-002 SRC-006 SRC-007">
```

封面、纯章节停顿页和封底可以没有 `data-source-refs`。模型补充的桥接标题或过渡句不创建虚假来源 ID；若整页包含新的分析判断，应明确标为分析或建议，而不是用户原文事实。

## 3. 允许与禁止的改写

允许：

- 调整顺序、拆分段落、把同一事实改成图表或结构图。
- 删除完全重复、没有新增信息的复述，但被合并的每个来源 ID 仍映射到成稿页。
- 忠实转述冗长句子，同时保留主体、因果关系、时间、范围、数量、条件和不确定性。
- 将过长原文放入多页、附录页或保真截图，而不是塞进极小字号。

禁止：

- 把“可能、预计、在特定条件下”改成确定结论。
- 删除反例、风险、统计口径、适用范围或限制条件，只保留正面结论。
- 将多个不同论点归并成一句泛化口号。
- 为适配 S03、S19、S28 等强结构版式而丢掉不适配的信息。
- 把模型推断、品牌话术或补充案例写成用户已经提供的事实。
- 仅因固定页数、最小字号或视觉留白要求而静默删减内容。

逐字引用、法务措辞、数字、公式、专有名词、决策结论和行动责任人默认不得改写。必须改写时先获得用户确认。

## 4. 内容放不下时的处理顺序

按以下顺序处理，越靠后的动作权限越高：

1. 删除纯视觉填充和无信息价值的重复标签。
2. 收紧局部间距、调整列宽或改用容量更高的已登记版式。
3. 将同一来源项拆到多页，或增加附录/证据页。
4. 对真正重复的表述做忠实合并，保留全部来源 ID 映射。
5. 若用户明确固定页数，报告完整保留所需页数与目标页数的冲突，请用户选择增加页数或进入 `editorial-summary`。
6. 只有用户批准后才省略来源项，并在覆盖清单中记录 `reason` 与 `userApproved: true`。

不得用降低正文到最小字号以下来伪装“完整保留”，也不得把未显示的原文藏在不可见 DOM、注释或交互层中冒充覆盖。

## 5. 交付前审计

运行：

```bash
node <SKILL_ROOT>/scripts/validate-swiss-deck.mjs path/to/index.html
```

校验器会在来源模式下自动读取同目录的 `content-coverage.json`，核对模式、ID、成稿页引用与遗漏审批。随后人工检查：

1. 每个原始语义单元是否都登记，尤其是数据口径、限制条件、反例、风险和行动项。
2. 忠实转述是否改变语气强度、因果关系、时间、范围或数字。
3. 每个 `included` 项是否在对应 slide 中真实可见，而不只是写了 ID。
4. 是否存在成稿新增但没有标明为分析/建议的事实性内容。
5. 向用户报告内容模式、覆盖项总数、包含项数、经批准遗漏项数及遗漏清单。

自动校验能发现清单和引用断裂，但不能判断文字是否真正忠实。最终语义核对仍是必需步骤。
